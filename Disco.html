Capítulo 01

Tabelas de Particionamento: MBR vs GPT

Antes de criar qualquer volume ou sistema de arquivos, o hardware e o sistema operacional precisam saber onde começam e terminam as divisões de um disco rígido ou SSD.

Padrão Legado (1983) Setor 0 (LBA 0)

MBR (Master Boot Record)

Introduzido com o IBM PC DOS 2.0, o MBR armazena informações de partição e o código do bootloader no primeiro setor de 512 bytes do disco. Por utilizar campos de 32 bits para endereçamento de setores LBA, possui gargalos físicos intransponíveis na era dos discos modernos.

  • ✕ Limite de 2.2 TB: Com setores convencionais de 512 bytes e limite de 32 bits ($2^{32} \times 512 = 2.199.023.255.552$ bytes), qualquer espaço além de 2 TB é inutilizado e não pode ser particionado.
  • ✕ Máximo de 4 Partições Primárias: Para contornar isso, é necessário converter uma primária em partição "Estendida" e criar partições "Lógicas" dentro dela.
  • ✕ Ponto Único de Falha: Não há cópia de segurança. Se o setor 0 sofrer corrupção de hardware ou gravação acidental, todas as tabelas de partição são perdidas.
  • ! Boot: Projetado para sistemas com BIOS Legada (CSM). Não inicializa nativamente sistemas operacionais via UEFI moderno sem módulos de compatibilidade.
Indicado apenas para: Pendrives antigos, sistemas legados de 32 bits ou máquinas industriais antigas.
Padrão Atual & Futuro LBA 1 a 33 + Cópia Final

GPT (GUID Partition Table)

Parte integrante da especificação UEFI. O GPT utiliza identificadores únicos universais (GUID) para cada partição e endereçamento LBA de 64 bits, eliminando as limitações do MBR e oferecendo alta confiabilidade de dados.

  • ✓ Capacidade quase infinita (9.4 Zettabytes): Endereçamento de 64 bits suporta até $18 \times 10^{18}$ bytes (9,4 ZB), garantindo compatibilidade com armazenamentos industriais por décadas.
  • ✓ Até 128 partições no Windows: Suporte nativo a dezenas de partições sem qualquer necessidade de partições estendidas ou lógicas complexas.
  • ✓ Redundância e Verificação CRC32: Mantém uma cópia de cabeçalho e tabela no final físico do disco. Possui checksums CRC32; se o setor for corrompido, o firmware recupera a tabela automaticamente.
  • ✓ Protective MBR: Grava um MBR de proteção no LBA 0 para impedir que utilitários antigos destruam a tabela GPT por engano.
Obrigatório para: Windows 11, Secure Boot, drives NVMe modernos e discos acima de 2 TB.
Característica MBR (Master Boot Record) GPT (GUID Partition Table)
Capacidade Máxima Suportada 2.2 Terabytes (TB) 9.4 Zettabytes (ZB) ($9.4 \times 10^9$ TB)
Número Máximo de Partições 4 Primárias (ou 3 Primárias + 1 Estendida) Até 128 no Windows (Ilimitado na teoria)
Tipo de Firmware / Boot BIOS Legada (Legacy) / Modo CSM UEFI (Unified Extensible Firmware Interface)
Mecanismo de Resiliência Nenhum (Setor 0 danificado = perda total) Checksum CRC32 + Cópia secundária de backup no fim do disco
Identificação das Partições Códigos Hexadecimais simples (ex: 0x07 NTFS) GUIDs de 128-bit globais exclusivos
Capítulo 02

Volumes: Simples, Estendido e Distribuído

Como os dados são organizados e distribuídos nas unidades de armazenamento físicas.

01

Volume Simples

1 Disco Físico Apenas

É a unidade padrão de armazenamento. Utiliza espaço livre contíguo de um único disco físico. Em discos dinâmicos, pode ser expandido dentro do próprio disco caso haja espaço contíguo ou não alocado adjacente.

Como grava: Grave sequencialmente em blocos no próprio drive de origem.
Tolerância a Falhas: Nenhuma nativa. Se o disco queimar, o volume é perdido.
Uso recomendado: Partição do Sistema Operacional (`C:`), discos secundários normais, armazenamento de arquivos individuais.
02

Volume Estendido

2 a 32 Discos Físicos (JBOD)

Conhecido também pelo conceito de Spanned Volume ou JBOD (Just a Bunch of Disks). Combina sobras de espaço de diferentes discos (podendo ter tamanhos e marcas completamente diferentes) em uma única letra de unidade lógica.

Como grava (Linear): Preenche completamente o Disco 1 primeiro. Somente quando o Disco 1 atinge 100%, ele começa a gravar no Disco 2.
Tolerância a Falhas: Zero. Se qualquer um dos discos falhar, a tabela do sistema de arquivos é destruída e o volume inteiro torna-se inacessível.
Uso recomendado: Aproveitar sobras de HDs velhos (ex: juntar 250 GB + 500 GB = 750 GB) para arquivos temporários sem valor crítico.
03

Volume Distribuído

2 a 32 Discos (RAID 0)

Tecnicamente chamado de Striped Volume ou RAID 0. Requer áreas de tamanho idêntico em cada disco participante. O foco principal não é a economia de sobras, mas sim a velocidade extrema.

Como grava (Striping Paralelo): Os dados são fatiados em blocos (stripes, ex: 64 KB). Bloco 1 vai para o Disco A, Bloco 2 para o Disco B simultaneamente.
Tolerância a Falhas: Risco Dobrado ($1 - (1-p)^n$). Se 1 disco queimar, 50% dos pedaços de cada arquivo desaparecem; perda imediata total.
Uso recomendado: Cache de edição de vídeo, renderização 3D, pastas temporárias de computação que já possuam backup externo.

Importante: Discos Básicos vs Dinâmicos & Storage Spaces (Windows)

No Windows, volumes Estendidos e Distribuídos exigem a conversão do disco de Básico para Dinâmico (que utiliza o LDM - Logical Disk Manager).

⚠️ Depreciação Atual: A Microsoft declarou o recurso de Discos Dinâmicos como obsoleto (deprecated) em versões recentes do Windows 10/11 e Windows Server. O substituto oficial e moderno da Microsoft chama-se Espaços de Armazenamento (Storage Spaces), que oferece pool de discos, camadas de paridade e melhor tolerância a falhas sem as travas do formato LDM. No entanto, o `diskpart` e a GUI ainda oferecem suporte aos volumes dinâmicos por retrocompatibilidade.

Capítulo 03

Sistemas de Arquivos: FAT32, NTFS, EXT4 e APFS

A partição define os limites físicos no disco, enquanto o Sistema de Arquivos determina a estrutura lógica onde dados, diretórios, permissões, metadados e registros de transações (journaling) são guardados.

Universal / Legado 1996 (Win 95 OSR2)

FAT32

File Allocation Table 32-bit

O padrão com maior compatibilidade global da história da computação. Qualquer Smart TV, console de videogame, rádio de carro, roteador, Windows, macOS ou Linux lê e grava em FAT32 sem drivers adicionais.

✕ Tamanho Máx. de Arquivo: 4 GB (limite estrito de 32 bits no cabeçalho).
✕ Tamanho Máx. Volume: 2 TB (Windows limita a 32 GB pelo utilitário padrão).
✕ Sem Journaling: Puxar o pendrive sem ejetar corrompe facilmente os arquivos.
✕ Sem Permissões: Não suporta ACLs nem permissões POSIX.
Ideal para: Pendrives de boot BIOS, firmwares de roteadores e compatibilidade com videogames retrô.
Padrão Windows 1993 (Windows NT)

NTFS

New Technology File System

Sistema de arquivos profissional desenvolvido pela Microsoft. Baseado na MFT (Master File Table), possui registro em diário (*journaling* com arquivo `$LogFile`), garantindo integridade contra falhas de energia e desligamentos bruscos.

✓ Recursos Corporativos: ACLs (permissões de usuário granular), cotas de disco e Shadow Copies (VSS).
✓ Criptografia & Compressão: Suporte nativo a EFS (*Encrypting File System*) e compressão transparente.
✓ Limite Gigante: Arquivos e partições de até 8 PB.
! Compatibilidade Mac: O macOS apenas lê NTFS nativamente (escrita exige software de terceiros ou FUSE).
Ideal para: Instalação do Windows (`C:`), discos internos de PCs e servidores corporativos Microsoft.
Padrão GNU/Linux 2008 (Kernel Linux)

EXT4

Fourth Extended Filesystem

O sistema de arquivos de referência da grande maioria das distribuições Linux e Android. Utiliza estrutura de **Inodes** (tabelas de descritores de metadados separadas do conteúdo do arquivo), alocação com *extents* e gravação diferida (*delayed allocation*).

✓ Alta Estabilidade: Journaling maduro com suporte a 3 modos (`ordered`, `journal` ou `writeback`).
✓ Permissões POSIX: Permissões Unix puras (owner/group/others, SUID, SGID, Sticky bit e ACLs).
✓ Limites: Arquivos até 16 TB e volumes até 1 Exabyte (EB).
! Windows/Mac: Não lê nativamente sem softwares auxiliares como WSL2 ou Paragon.
Ideal para: Servidores Linux, contêineres Docker, estações de trabalho e discos raiz de distribuições.
Padrão Apple 2017 (macOS High Sierra)

APFS

Apple File System (Substituiu HFS+)

Criado especificamente para memórias Flash e drives SSDs da Apple. Revolucionou o ecossistema com arquitetura de Copy-on-Write (CoW), clonagem instantânea de arquivos sem consumir espaço em disco e suporte a snapshots nativos integrados ao Time Machine.

✓ Clones Instantâneos: Duplicar um arquivo de 50 GB leva milissegundos e ocupa 0 bytes extras até ser modificado.
✓ Criptografia Nativa: Suporte multi-chave integrado ao hardware do chip Apple Silicon (T2, M1, M2, M3, M4).
✓ Space Sharing: Múltiplos volumes compartilham o mesmo pool de armazenamento dinâmico.
✕ Exclusividade Apple: Incompatível nativamente com Windows e Linux.
Ideal para: Macs modernos (MacBook, Mac mini, Mac Studio), iPhones, iPads e SSDs externos exclusivos Apple.
exFAT (Ponte Universal)

Criado pela Microsoft para substituir o FAT32 em pendrives e cartões SD. Suporta arquivos maiores que 4 GB e funciona nativamente com permissão total de leitura e gravação no Windows, macOS e Linux moderno.

Btrfs / XFS (Linux Next-Gen)

Btrfs: Foco em Copy-on-Write, subvolumes e snapshots (padrão no Fedora e openSUSE). XFS: Foco em altíssimo paralelismo para arquivos gigantescos e bancos de dados (padrão no RHEL/CentOS).

ZFS (OpenZFS)

Considerado o ápice da integridade de dados para servidores NAS corporativos (TrueNAS). Combina gerenciador de volumes, RAID por software e checagem contínua contra corrupção silenciosa de bits (*bit rot*).

Implementando no Microsoft Windows

Como particionar e configurar MBR, GPT e os diferentes volumes utilizando a interface gráfica (`diskmgmt.msc`) e o utilitário nativo de terminal `diskpart`.

1 Inicializar Disco Físico e Definir Tabela (MBR ou GPT) 

# Abra o PowerShell ou CMD como Administrador e execute:
diskpart

# Liste os discos conectados para identificar o número correto
list disk

# Selecione o disco de destino (ATENÇÃO: confirme o número para não apagar o sistema!)
select disk 1

# Limpa todas as informações e partições antigas existentes
clean

# CONVERTER PARA GPT (Recomendado para UEFI e discos > 2TB)
convert gpt

# OU CONVERTER PARA MBR (Apenas se for BIOS legada / compatibilidade)
# convert mbr

2 Criar Volume Simples (Partição Básica Normal) 

# Selecionar o disco inicializado
select disk 1

# Cria uma partição primária usando todo o espaço livre
create partition primary

# Formata o volume em NTFS rapidamente e com rótulo
format fs=ntfs quick label="Dados_Simples"

# Atribui uma letra de unidade automática (ex: E:)
assign

# Sair do utilitário
exit

3 Criar Volume Estendido (Spanned - Junta 2 ou mais discos)

Exige conversão prévia dos discos envolvidos para discos dinâmicos.

diskpart

# Converter ambos os discos para dinâmicos
select disk 1
clean
convert dynamic

select disk 2
clean
convert dynamic

# Cria o volume estendido combinando os discos 1 e 2
# disk=1,2 pega todo o espaço livre restante de ambos e soma em um só
create volume span disk=1,2

# Formatar e atribuir letra
format fs=ntfs quick label="Volume_Estendido"
assign letter=S
exit

4 Criar Volume Distribuído (Striped / RAID 0 de Alto Desempenho) 

diskpart

# Certifique-se de que os discos estão limpos e são dinâmicos
select disk 1
clean
convert dynamic

select disk 2
clean
convert dynamic

# Cria o volume distribuído em faixas idênticas entre disk 1 e disk 2
create volume stripe disk=1,2

# Formatação e montagem
format fs=ntfs quick label="Stripe_RAID0"
assign letter=R
exit
Como abrir:

Pressione as teclas Win + R, digite diskmgmt.msc e pressione Enter.

  1. Inicializar o Disco em GPT: Ao abrir o utilitário com um novo drive, uma janela pop-up surgirá perguntando: "Você deve inicializar um disco antes que o Gerenciamento de Disco Lógico possa acessá-lo". Escolha o botão de opção GPT (GUID Partition Table) e confirme com OK.
  2. Criar Volume Simples: Clique com o botão direito sobre o espaço "Não Alocado" em preto do disco $\rightarrow$ selecione Novo Volume Simples $\rightarrow$ defina o tamanho $\rightarrow$ escolha a letra de montagem e o sistema de arquivos (NTFS).
  3. Criar Volume Estendido (Spanned): Clique com o botão direito no espaço livre do primeiro disco $\rightarrow$ Novo Volume Estendido $\rightarrow$ no assistente, selecione os outros discos disponíveis na coluna da esquerda e clique no botão "Adicionar" $\rightarrow$ defina o espaço de cada um $\rightarrow$ confirme. O Windows avisará que converterá os discos para dinâmicos.
  4. Criar Volume Distribuído (Striped / RAID 0): Clique com o botão direito no espaço não alocado $\rightarrow$ selecione Novo Volume Distribuído $\rightarrow$ adicione o segundo disco. Observe que o assistente selecionará automaticamente a mesma quantidade de megabytes em ambos os discos.

Implementando no GNU/Linux

No ecossistema Linux, o particionamento base é feito via ferramentas como fdisk, gdisk ou parted. Volumes estendidos são tradicionalmente gerenciados pelo LVM (Logical Volume Manager) e volumes distribuídos via mdadm (Software RAID).

1 Particionamento GPT via Terminal (fdisk / parted)

Base

Em distribuições modernas (Ubuntu, Debian, RedHat, Arch), o próprio utilitário fdisk suporta GPT nativamente, ou pode-se usar o parted para scripts rápidos. 

# 1. Identificar os discos conectados
lsblk -f

# 2. Criar uma nova tabela de partição GPT no disco /dev/sdb via parted (não-interativo)
sudo parted /dev/sdb --script mklabel gpt

# 3. Criar uma partição primária ocupando 100% do disco
sudo parted /dev/sdb --script mkpart primary ext4 0% 100%

# 4. Formatar em EXT4 e criar ponto de montagem
sudo mkfs.ext4 -L "MeusDados" /dev/sdb1
sudo mkdir -p /mnt/dados
sudo mount /dev/sdb1 /mnt/dados

# 5. Adicionar ao /etc/fstab para montagem persistente no boot:
# Obtenha o UUID da partição:
sudo blkid /dev/sdb1
# Adicione a linha no fstab:
# UUID=xxxx-xxxx /mnt/dados ext4 defaults 0 2

2 Volume Estendido (Spanned) usando LVM (Logical Volume Manager)

Equivalente Flexível

O LVM é o padrão industrial no Linux para unir múltiplos discos físicos (Physical Volumes - PV) em um único grupo de armazenamento (Volume Group - VG), permitindo criar partições lógicas (Logical Volumes - LV) que se estendem dinamicamente através de discos distintos. 

# Supondo dois discos livres: /dev/sdb e /dev/sdc

# PASSO 1: Inicializar os discos como Volumes Físicos LVM (PV)
sudo pvcreate /dev/sdb /dev/sdc

# PASSO 2: Criar um Grupo de Volumes (VG) unindo os dois drives
sudo vgcreate vg_storage /dev/sdb /dev/sdc

# PASSO 3: Criar um Volume Lógico (LV) usando 100% da soma do espaço dos dois discos
sudo lvcreate -l 100%FREE -n lv_spanned vg_storage

# PASSO 4: Formatar o volume unificado e montar
sudo mkfs.xfs /dev/vg_storage/lv_spanned
sudo mkdir -p /mnt/spanned_pool
sudo mount /dev/vg_storage/lv_spanned /mnt/spanned_pool

# Exibir relatório de alocação de blocos
sudo vgs
sudo lvs

3 Volume Distribuído (Striped / RAID 0) usando `mdadm`

Alta Velocidade

Para obter máxima taxa de transferência contínua distribuindo blocos simultaneamente em vários discos físicos, utilizamos o utilitário nativo de Software RAID do kernel Linux (mdadm). 

# Instalar mdadm se necessário (Debian/Ubuntu: sudo apt install mdadm)

# PASSO 1: Criar o Array RAID 0 com chunk de 64 KB
sudo mdadm --create --verbose /dev/md0 --level=0 --raid-devices=2 /dev/sdb /dev/sdc

# PASSO 2: Verificar o status de sincronização
cat /proc/mdstat

# PASSO 3: Formatar o dispositivo virtual RAID /dev/md0
sudo mkfs.ext4 -F /dev/md0
sudo mkdir -p /mnt/raid0_stripe
sudo mount /dev/md0 /mnt/raid0_stripe

# PASSO 4: Salvar a configuração do RAID para persistência pós-reinicialização
sudo mdadm --detail --scan | sudo tee -a /etc/mdadm/mdadm.conf
sudo update-initramfs -u

Implementando no Apple macOS

O macOS utiliza o poderoso utilitário de terminal diskutil e a ferramenta gráfica Utilitário de Disco (Disk Utility) para gerenciar tabelas GPT, containers APFS e criar volumes RAID nativos.

1 Listar e Formatar Discos em APFS, exFAT ou FAT32

diskutil 
# 1. Identificar os discos conectados (ex: /dev/disk2)
diskutil list

# 2. Formatar disco em APFS com tabela GPT (padrão Mac)
diskutil eraseDisk APFS "SSD_Mac" GPT /dev/disk2

# 3. Formatar pendrive em exFAT (compatível com Mac, Windows e Linux)
diskutil eraseDisk ExFAT "USB_Universal" GPT /dev/disk2

# 4. Formatar pendrive em FAT32 clássico (MS-DOS FAT)
diskutil eraseDisk FAT32 "USB_FAT32" MBR /dev/disk2

# 5. Adicionar um novo volume compartilhado ao mesmo Container APFS (Space Sharing)
diskutil apfs addVolume disk2s1 APFS "NovoVolumeDados"

2 Criar Volumes RAID 0 (Distribuído) e Concatenação (Estendido)

diskutil appleRAID

O subsistema appleRAID permite fundir dois discos físicos em um array distribuído (stripe) ou estendido/linear (concat). 

# Criar Volume Distribuído (Stripe / RAID 0) entre dois discos (/dev/disk2 e /dev/disk3):
diskutil appleRAID create stripe "Mac_Stripe_RAID0" APFS /dev/disk2 /dev/disk3

# Criar Volume Estendido (Linear / Concatenação JBOD) somando dois discos:
diskutil appleRAID create concat "Mac_Spanned_Concat" APFS /dev/disk2 /dev/disk3

# Verificar status dos arrays RAID ativos:
diskutil appleRAID list

# Excluir / desmanchar o arranjo RAID criado:
# diskutil appleRAID destroy <UUID-do-Array>

Comandos Essenciais de Verificação e Manutenção de Disco

Equivalentes entre Windows, Linux e macOS:

Windows (chkdsk)

chkdsk E: /F /R

/F corrige erros lógicos; /R localiza e recupera setores defeituosos (bad sectors).

Linux (fsck / e2fsck)

sudo fsck -fvy /dev/sdb1

-f força verificação; -v verbose; -y responde 'sim' para consertar automaticamente.

macOS (First Aid / fsck)

diskutil verifyVolume /dev/disk2s1

Para reparar: diskutil repairVolume /dev/disk2s1

Qual Arquitetura Escolher?

Árvore de Decisão Rápida

Responda mentalmente ao seu cenário para identificar a combinação exata de partição + volume + sistema de arquivos:

Cenário A

Instalação de Windows ou SSD Padrão

SSD NVMe moderno para Windows 10/11 ou jogos convencionais em PC.

Escolha recomendada: GPT + Volume Simples + NTFS
Cenário B

Pendrive ou SSD Externo Multiplataforma

Você transita arquivos pesados (filmes, backups) entre Windows, Mac e Linux com frequência.

Escolha recomendada: GPT + Volume Simples + exFAT
Cenário C

Servidor Linux / Estação de Trabalho

Ambiente Linux corporativo, nós de Kubernetes, Docker ou armazenamento de desenvolvimento.

Escolha recomendada: GPT + LVM + EXT4 (ou Btrfs)
Cenário D

Ecossistema Exclusivo Apple

Armazenamento interno ou externo para MacBook, Mac Studio com suporte a Time Machine e snapshots.

Escolha recomendada: GPT + Container APFS (Space Sharing)
